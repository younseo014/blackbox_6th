# 업무 인식 구조 수정 — 2026-11-13

## 자료 사용과 검증 범위

3차 첨부 자료는 이전 구현의 실패 양상을 보여주는 테스트 사례다. 이번 수정에서 해당 자료를 학습에 추가하거나 실제 시각·수행 순서·횟수를 코드에 넣지 않았고, 그 자료의 결과에 맞춰 기준을 최적화하지 않았다. 개발/회귀 자료에서 좋아진 결과를 독립 정확도 향상으로 보고하지 않는다.

수정 전 소스는 로컬 `work/recognition-baseline-2026-11-13.zip`에 보존했다. 이 파일과 개인 자료는 Git 추적 대상이 아니다. 기존 CSV와 좌표 ZIP도 변경하지 않는다. 과거 ZIP에 당시 개인 학습 표본 전체의 고정 사본이 없으므로 기존 개인화 판정을 완벽히 소급 재현할 수 있다고 주장하지 않는다.

새 배포 버전은 **0.1.1**, 인식 버전은 **work-recognition-v3**, 특징 버전은 **shoulder-arms-hands-v1**이다. 영상 가중치를 새로 학습하거나 교체한 변경은 아니다.

## 구현 변경

1. **구간과 라벨 분리**: 개인 표본으로 구간을 찾은 업무명은 제안 근거로만 남긴다. 동일한 구간을 등록된 모든 개인 업무와 다시 비교한다. 1위만 비교하거나, 경쟁 후보가 없을 때 차이를 1로 주는 처리를 하지 않는다. 구역·단순 이동의 약한 힌트만 있으면 업무명을 미확정으로 기록한다.
2. **공통 특징**: 검색과 최종 비교가 같은 어깨 기준 좌표·팔꿈치/손목·양손 상대 위치·관측된 손끝 모양·이동 방향·상대 속도를 사용한다. 손이 미검출이면 비교에서 제외한다. 전체 수행이 느려지는 것은 별도 라벨의 조건이 아니다. 기존의 일반 개발자 동작 분류기는 유지한다.
3. **대표 표본**: 저장 순서의 처음/중간/마지막 대신 수동 확인 표본을 우선 출발점으로 하고 관측 품질과 수행 다양성을 고려한다. 계산량 예산은 유효 표본 수의 제곱근이며 검증된 최적 개수가 아니다. 같은 모양의 중복은 추가 대표로 뽑지 않는다. 한 세션 분석 중 같은 참조 객체의 선택을 재사용한다.
4. **경쟁 후보 선택**: 겹침 40% 규칙 대신 한 사람의 같은 시간대 후보를 전체 시간축에서 비중첩 후보 집합으로 선택한다. 전체 참조 순서를 만족한 구간의 일치도를 사용하고, 탈락한 경쟁 후보는 보고서에 보존한다. 관측된 완료가 연속으로 있는 비중첩 업무는 같은 이름이어도 따로 남는다. 다중 업무를 동시에 수행하는 상황을 해결한 모델은 아니다.
5. **잔여 움직임 보존**: 개인 구간과 일부 겹친 움직임 전체를 버리지 않는다. 겹친 부분 밖의 앞뒤 움직임은 잔여 구간으로 남기고 경계 미확인으로 표시한다. 독립 구간을 만들기 어려운 짧은 관측도 원좌표와 처리 기록을 보존한다.
6. **경계 정밀화**: 검색 간격 주변을 실제 저장 프레임으로 다시 검사해 참조 시작/종료와 정렬한다. 새 좌표를 보간하지 않고 이웃 구간을 넘어가지 않는다. 이는 표본 경계의 시간 해상도를 보정하는 것이며 물체를 놓는 의미상의 완료를 보장하지 않는다. 작업별 물체·완료 인식 성능은 별도 검증이 필요하다.
7. **긴 수행과 정지 유지**: 참조 수행시간의 0.5~3배 밖이라는 이유로 완전한 순서 일치를 버리는 조건을 제거했다. 긴 관측 업무는 검색 창 길이만으로 누락되지 않도록 별도 검색한다. 내부 정지는 제거하지 않고, 추적 공백과 미관측 경계는 불확실 상태로 남긴다. 이미 존재하는 최소 프레임/관측 기준은 유지한다.
8. **자동 학습의 순환 방지**: `sequence_model`로만 생성된 과거 표본은 독립 기준 표본으로 재사용하지 않는다. 개인 표본만으로 충분히 분류한 결과도 자동 기록은 유지하지만 스스로 다음 표본을 계속 늘리지 않는다. 독립 영상 근거가 같은 업무를 지지할 때 기준 표본으로 자동 추가한다. 영상 근거만으로 새로운 업무를 등록할 수 있어 매 건 또는 초기 10건 수동 확인을 필수로 만들지 않는다. 영상 근거가 없거나 약한 상황의 자동 등록은 해결됐다고 주장하지 않는다.
9. **학습/분석 분리**: 분석 세션은 기준 표본을 갱신하지 않는다. 자체테스트의 기준선과 업종 메타데이터는 사용자 모드의 설정을 차용하지 않고 카페/학습·분석 단계와 기준선 0으로 기록한다. 과거 데이터는 소급 변경하지 않는다.

## 재현 및 진단 기록

촬영 시작 시점에 인식/특징 버전과 개인 표본 참조 전체를 `recognitionContext`로 고정한다. 처리한 참조 수, 생성/선택/경쟁/잔여/불완전 후보와 이유, 좌표 공백을 `recognitionReport`로 좌표 ZIP 안에 보존한다. 수동 정정 후에도 자동 판정 근거와 원래 자동 경계는 보존한다.

CSV에 인식 버전, 최종 판별 근거, 모든 개인 후보 점수와 차이, 독립 근거, 동작 기준 표본 반영 여부, 약한 맥락 힌트, 구간 탐색 라벨, 경계 보정 전 시각을 추가했다. 판별 불가로 철회하면 현재 기준 표본 반영 상태도 해제한다. 새/과거 테스트 구성은 계속 구별된다.

영상 모델은 판정 기준과 가중치를 유지한다. 최상위 후보만 저장하던 방식에 전체 후보 점수, 실제 입력 크기/중앙 크롭 범위, 관측된 팔 관절이 입력에 포함되는 비율을 추가했다. 이미지·음성·임베딩은 저장하지 않는다. 이 진단만으로 영상 인식 성능이 개선됐다고 보고하지 않는다. 영상 원본이 없는 기존 스켈레톤 자료에서는 입력 크롭·작업영역의 실제 인식 효과를 재검증할 수 없다.

## 평가 실행

`npm run eval:recognition -- --cases /외부경로/cases.json --output /외부경로/report.json`

각 case는 `name`, `split`(development/heldout/regression/unlabelled), `recording`, `expected`(정답 구간/업무 배열 또는 null)를 가진다. 정답은 점수 계산에만 전달한다.

- 참조는 `references` 배열로 label/recording/startMs/endMs/labelSource를 명시하거나, 기록에 들어 있는 고정 bank와 `referenceRecordings`(세션 ID→파일)를 사용한다.
- 참조가 없으면 `allowColdStart: true`를 명시해야 한다. 평가 정답으로 참조를 추정하거나 자동 생성하지 않는다.
- 학습/평가가 같은 파일·세션이거나 파일 내용이 같으면 실행을 거부한다.
- 기존 자동 결과는 `baselinePredictions` JSON을 지정하면 별도 열로 비교한다. 과거 결과를 새 기준으로 다시 만들었다고 가장하지 않는다.
- 라벨을 보지 않고 시간 겹침으로 일대일 대응한다. 업무별 혼동, 누락, 추가/중복 후보, 병합 의심, 경계 오차 중앙값/P90, 라벨 성공과 자동 처리 성공, 보류 수를 구분한다. 정답 시각이 없으면 경계 정확도를 계산하지 않는다.

## 운영 기준의 한계

기존 거리/점수 기준을 유지한 부분과 새 특징 조합·대표 개수 예산은 독립적인 실제 카페 개발 자료에서 보정되지 않았다. 이미지 점수나 개인 표본 일치 점수를 확률로 해석하면 안 된다. 새 버전의 실제 정확도 향상, 다른 사람/설치 각도에 대한 일반화, 치매 관련 임상 성능은 아직 검증되지 않았다.

카메라별 보정 3D 재구성·시점 불변 인식·장시간 전체 종료 분석 메모리 문제는 이번 수정으로 해결하지 않았다. 한 시점의 정규화된 좌표를 사용하며 일부 특징은 기존 16:9 가정을 유지한다. 새로운 영상과 독립 정답 시각이 있는 촬영으로 실측해야 한다.

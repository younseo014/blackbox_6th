# 사람 스켈레톤·동작 인식·라벨링 성능 보고서

- 평가일: 2026-09-10
- 평가 대상: 현재 내장 카메라 + 웹캠 구조, 개발자 모드의 개인 동작 학습/판별 기능
- 평가 방법: 구현 코드 검토, 단위 테스트 실행, 기존 합성 벤치마크 검토, 원 논문·공식 문서 대조

## 1. 결론

현재 시스템은 **한 명의 사용자가 소수의 동작을 직접 등록하고 다시 재현하는 개인화 실험용 프로토타입**으로는 작동한다. 그러나 실제 카메라 환경의 정확도를 수치로 입증할 근거는 아직 없다.

| 영역 | 현재 판단 | 근거 | 가장 큰 한계 |
|---|---|---|---|
| 사람 스켈레톤 인식 | 기반 모델은 강하지만 현장 성능 미측정 | MediaPipe Heavy, GPU 우선, VIDEO 추적, 상반신 잠금 지원 | 가림·잘림·역광·빠른 움직임별 검출률과 떨림을 측정하지 않음 |
| 동작 인식 | 소수 개인 동작에는 유효한 규칙 기반 분류기 | 어깨 기준 정규화, 좌우 반전 비교, DTW, 최근접 예제 비교 | 비슷한 동작, 촬영 세션 변화, 물체가 필요한 동작에 대한 일반화 한계 |
| 동작 라벨링 | 기능은 있으나 신뢰도 수치가 확률은 아님 | 최상위 거리와 차상위 거리로 휴리스틱 신뢰도 계산 | 미등록 동작 거부, 클래스별 임계값, 확률 보정이 없음 |

가장 먼저 해야 할 일은 더 큰 모델을 붙이는 것이 아니라 **실제 카메라 검증 세트와 측정 화면을 만드는 것**이다. 그다음 한 사람이라는 실험 조건을 활용해 `numPoses=1`, 관절 품질 필터, 흔들림 보정, 자동 구간 자르기, 미등록 동작 거부를 적용하는 것이 비용 대비 효과가 가장 크다.

## 2. 현재 구현과 확인된 성능

### 2.1 사람 스켈레톤 인식

현재 구현은 다음 조건을 사용한다.

- MediaPipe Pose Landmarker Heavy 모델
- GPU 우선, 실패 시 CPU 전환
- VIDEO 모드 추적
- 최대 3개 자세 후보를 검출한 뒤 대상 잠금 로직으로 한 사람 선택
- 검출 0.40, 존재 0.40, 추적 0.35의 비교적 관대한 임계값
- 상반신만 보이는 경우에도 어깨·팔 좌표로 대상 잠금
- 일시 검출 실패 시 450ms까지 마지막 자세 유지, 650ms 뒤 재획득 허용
- 손은 별도의 Hand Landmarker로 검출하고 잠긴 사람의 손목 주변 결과만 결합

MediaPipe 공식 문서상 Pose Landmarker는 정규화 좌표와 3차원 월드 좌표를 모두 반환하며, `numPoses` 기본값은 1이고 기본 검출·존재·추적 임계값은 각각 0.5다. 현재 앱은 정규화 좌표를 주로 사용하고 월드 좌표는 저장하지 않는다. 따라서 카메라 거리와 시점 변화에 대한 불변성이 제한된다. [MediaPipe Pose Landmarker 공식 문서](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js?authuser=7), [공식 구현](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/web/vision/pose_landmarker/pose_landmarker.ts)

### 2.2 동작 인식

현재 분류기는 신경망을 새로 학습하는 방식이 아니라, 사용자가 등록한 좌표 예시와 새 동작을 비교하는 **개인화 템플릿 분류기**다.

1. 어깨 중심과 어깨너비로 좌표를 정규화한다.
2. 어깨·팔·골반·무릎·발목과 손 특징을 사용한다.
3. 시퀀스를 28개 시점으로 재표본화한다.
4. 수행 속도 차이는 DTW로 정렬한다.
5. 정면/후면 차이를 줄이기 위해 좌우 반전 결과도 비교한다.
6. 각 라벨에서 가장 가까운 예시 2개의 평균 거리를 사용한다.

이 방식은 데이터가 5~10회뿐일 때 단순하고 유용하다. 다만 손으로 정한 특징과 거리 함수는 표현력과 일반화에 한계가 있다. ST-GCN 원 논문도 수작업 관절·규칙 기반 표현의 한계를 지적하고, 골격 그래프의 공간·시간 패턴을 데이터에서 학습하는 방식을 제안한다. [ST-GCN 원 논문](https://ojs.aaai.org/index.php/AAAI/article/download/12328/12187)

### 2.3 동작 라벨링

현재 `신뢰도`는 거리 점수와 1·2위 간격을 조합한 휴리스틱 값이며, 0.52 이상이면 일치로 표시한다. 이 값이 80%라고 해서 실제 정답 확률이 80%라는 뜻은 아니다. 학습 모델의 출력조차 별도 보정 없이는 실제 정답 확률과 어긋날 수 있다는 것이 알려져 있다. [Guo 외, On Calibration of Modern Neural Networks](https://proceedings.mlr.press/v70/guo17a/guo17a.pdf)

현재는 등록된 라벨끼리 경쟁하는 폐쇄형 분류에 가깝다. 등록되지 않은 행동, 준비 자세, 카메라 조정, 정지 상태를 충분히 학습하지 않았기 때문에 가장 비슷한 기존 라벨을 잘못 선택할 가능성이 있다.

## 3. 현재 확보된 수치와 해석 범위

### 자동 테스트

- 2026-09-10 실행 결과: **123개 중 123개 통과**
- 포함 범위: 상반신 자세 잠금, 전신↔상반신 전환, 대상 재획득, 손 연결, 정면/후면 좌우 반전, 카메라 인계, 속도 변화, 좌표 부족 거부, 합성 동작 분류

이는 코드 회귀 방지 성능이지 현장 정확도가 아니다. 테스트 데이터가 구현 규칙과 같은 가정으로 만들어졌기 때문이다.

### 기존 합성 벤치마크

- 구성: 9개 동작 × 미사용 시드 10개 × 4개 조건 = 360건
- 이전 선형 정렬 + 중앙값 방식: **340/360, 94.44%**
- 현재 DTW + 최근접 2개 방식: **360/360, 100%**
- 향상: **+5.56%p**

이 결과는 속도 변화와 상반신 합성 조건에서 회귀가 줄었음을 보여준다. 그러나 학습·평가 데이터가 같은 합성 생성 규칙에서 나왔으므로 실제 사람, 옷, 조명, 가림, 카메라 각도에 대한 일반화 근거로 사용할 수 없다.

### 아직 알 수 없는 실제 성능

현재 자료만으로 다음 수치를 정직하게 제시할 수 없다.

- 실제 상반신/전신 스켈레톤 검출률
- 관절별 좌표 오차와 떨림
- 실제 동작별 precision, recall, macro-F1
- 미등록 동작 오인식률
- 정면과 후면, 내장 카메라와 웹캠 사이 정확도 차이
- 표시되는 신뢰도와 실제 정답률의 일치 정도

따라서 현재 실제 정확도는 **미측정**이다. `100%`는 합성 회귀 세트에만 적용된다.

## 4. 예상 실패 원인

1. **입력 품질:** 손목·팔꿈치 가림, 화면 가장자리 잘림, 역광, 모션 블러가 좌표 누락과 점프를 만든다.
2. **2D 시점 의존성:** 정규화된 화면 좌표만으로는 정면과 후면뿐 아니라 사선, 카메라 높이·거리 변화까지 충분히 보정하기 어렵다.
3. **낮은 기록 빈도:** 포즈 검출 루프는 약 15FPS인데 분류용 저장은 10FPS다. 빠른 손 동작의 일부가 사라질 수 있다.
4. **고정 길이 표현:** 모든 동작을 28개 시점으로 압축하므로 짧은 핵심 순간이나 여러 단계로 된 동작이 희석될 수 있다.
5. **수동 구간:** 촬영 시작·종료에 준비 자세가 섞이면 동작보다 경계 차이를 학습한다.
6. **예제 오염:** 5~10회 중 잘못 촬영된 예시가 최근접 판단을 왜곡한다.
7. **행동 의미의 한계:** 서빙과 설거지가 비슷한 팔 궤적을 보이면 골격만으로 물체·작업 맥락을 구별하기 어렵다.
8. **미등록 행동 부재:** 알 수 없는 행동을 명시적으로 학습·검증하지 않아 강제 라벨링 위험이 있다.
9. **다중 카메라 기하 보정 부재:** 현재 좌우 반전과 연속성 보정은 유용하지만, 카메라 내부·외부 파라미터를 이용한 실제 3차원 좌표 통합은 아니다. OpenCV는 고정 카메라 사이의 intrinsic/extrinsic 보정과 좌표 정합 절차를 공식 제공한다. [OpenCV 다중 카메라 보정 문서](https://docs.opencv.org/5.0/main_modules/calib.html)

## 5. 최대 성능을 위한 개선 계획

### P0 — 실제 성능 측정 장치부터 추가

가장 높은 우선순위다. 모델을 바꿔도 같은 검증 세트로 전후를 비교하지 못하면 향상 여부를 알 수 없다.

- 동작별 최소 20~30회, 3일 이상 나누어 촬영
- 정면·후면·사선, 가까움·멀어짐, 밝음·어두움, 빠름·느림을 포함
- 학습에 쓰지 않은 촬영 날짜 전체를 검증 세트로 격리
- 등록되지 않은 행동과 정지 상태도 별도 수집
- 개발자 화면에 아래 지표 표시

| 층 | 필수 지표 |
|---|---|
| 스켈레톤 | 사람 획득률, 유효 상반신 프레임 비율, 관절별 누락률, 연속 누락시간 p95, 어깨너비 대비 좌표 떨림, 카메라 인계 실패 수, 처리 FPS |
| 동작 | 클래스별 precision/recall/F1, macro-F1, 혼동행렬, 구간 시작·끝 오차, 판별 지연 |
| 라벨 | 미등록 행동 false accept rate, 보류율, 보류를 제외한 정확도, confidence reliability diagram, ECE/Brier score |

공개 골격 행동 데이터셋도 cross-subject와 cross-view 평가를 분리한다. NTU RGB+D는 60개 클래스 56,880개 샘플, 확장판은 120개 클래스 114,480개 샘플 규모다. 이는 5~10회 개인 예제로 범용 인식 성능을 기대하기 어렵다는 규모상의 근거다. [NTU RGB+D 공식 페이지](https://rose1.ntu.edu.sg/dataset/actionRecognition/), [CVPR 원 논문](https://www.cv-foundation.org/openaccess/content_cvpr_2016/papers/Shahroudy_NTU_RGBD_A_CVPR_2016_paper.pdf)

### P1 — 기존 구조에서 가장 큰 개선

1. **한 사람 조건에 맞춰 `numPoses=1`로 변경**  
   불필요한 두 후보 검출과 후보 선택 모호성을 없애고 처리 여유를 확보한다. 다만 실제 기기에서 검출률·FPS를 전후 측정한 뒤 확정한다.

2. **월드 좌표 저장 및 2D 좌표와 병행**  
   MediaPipe가 반환하는 미터 단위 3D 월드 좌표를 동작 특징에 추가한다. 상반신 잘림에서는 품질이 나쁠 수 있으므로 2D 좌표를 대체하지 말고 품질에 따라 혼합한다. BlazePose 계열은 단일 RGB 영상에서 3D 전신 랜드마크를 추정하도록 설계됐다. [BlazePose 원 논문](https://arxiv.org/abs/2006.10204), [BlazePose GHUM](https://arxiv.org/abs/2206.11678)

3. **관절별 품질 판정으로 변경**  
   단순히 유효 프레임 6개를 세는 대신 어깨·팔꿈치·손목의 가시성, 좌표 점프, 뼈 길이 급변을 검사한다. 필요한 관절이 나쁜 샘플은 자동으로 재촬영시킨다.

4. **가시성 기반 흔들림 보정과 짧은 누락 보간**  
   관절별 One Euro Filter를 적용하고, 품질이 높은 점은 빠르게 반응시키며 낮은 점은 더 부드럽게 처리한다. 이 필터는 저속 떨림과 고속 지연 사이의 절충을 적은 계산량으로 조절하도록 제안됐다. [One Euro Filter 원 논문](https://direction.bordeaux.inria.fr/~roussel/publications/2012-CHI-one-euro-filter.pdf)

5. **실제 처리 여유가 있으면 저장 빈도를 15~20FPS로 상향**  
   먼저 기기별 처리시간을 측정한다. 프레임 지연이 늘면 10FPS보다 결과가 나빠질 수 있으므로 무조건 올리지 않는다.

6. **자동 구간 자르기**  
   0.5초 이상 안정된 준비 자세 뒤에 녹화를 시작하고, 움직임 에너지로 앞뒤 정지 구간을 제거한다. 같은 동작의 경계 차이를 줄이는 가장 값싼 개선이다.

### P2 — 동작 분류와 라벨 신뢰성 개선

- 좌표뿐 아니라 관절각, 뼈 방향, 속도, 가속도를 함께 비교
- 클래스마다 대표 예시를 medoid로 선택하고 이상 예시는 학습 세트에서 제외
- 검증 데이터로 클래스별 일치 임계값을 학습
- `미등록/기타/정지` 예시를 추가하고 1위 점수가 낮거나 1·2위 차이가 작으면 라벨을 보류
- 연속 분석에서는 겹치는 창의 다수결과 진입/이탈 임계값을 달리하는 히스테리시스로 라벨 깜빡임 방지
- 검증 세트에서 confidence를 보정해 화면의 퍼센트가 실제 정답률과 가까워지게 함

소수 개인 예제 단계에서는 이 개선까지가 적절하다. 데이터가 부족한 상태에서 곧바로 큰 신경망을 추가하는 것은 복잡성만 늘릴 가능성이 높다.

### P3 — 충분한 실제 데이터가 모인 뒤 학습 모델 도입

동작별·환경별 데이터가 충분해지고 템플릿 방식의 혼동이 실제로 확인되면 다음 순서로 올린다.

1. 관절·뼈·속도 스트림을 입력으로 하는 작은 TCN 또는 ST-GCN 학습
2. 시점 회전, 수행 속도, 좌우 반전, 일부 관절 누락 증강
3. 촬영 날짜·카메라 단위로 분리한 검증
4. 골격만으로 구별하기 어려운 작업에 한해 RGB의 물체/손 영역 특징과 결합

RGB 결합은 서빙 도구와 설거지 도구처럼 동작 의미를 결정하는 물체를 구분할 수 있지만, 저장 용량과 개인정보 부담이 커진다. 가능하면 영상은 저장하지 않고 기기 안에서 특징만 계산해야 한다.

### P4 — 두 카메라 성능의 최종 단계

- 카메라별 시간 오프셋 측정 및 보정
- 체커보드 등을 이용한 intrinsic/extrinsic 보정
- 각 카메라의 월드 좌표를 공통 매장 좌표계로 변환
- 두 화면이 겹치면 관절 품질이 높은 시점을 선택하거나 3차원 결합
- 화면이 겹치지 않으면 위치·속도·예상 이동시간과 불확실성으로 인계
- 카메라별 리플레이는 분리하고, 공통 타임라인에는 최종 선택된 스켈레톤 하나만 표시

## 6. 권장 처리 구조

```text
카메라
  → MediaPipe 1인 포즈(2D + world)
  → 관절 품질 검사
  → 흔들림 보정·짧은 누락 보간
  → 공통 신체 좌표계 변환
  → 자동 동작 구간 분할
  → 개인화 분류기(DTW/kNN)
  → 미등록 동작 거부 + 보정된 신뢰도
  → 시간창 투표로 최종 라벨
```

실제 데이터에서 템플릿 분류기의 한계가 확인된 경우에만 분류기 부분을 ST-GCN/TCN으로 교체한다. 앞단의 품질 검사와 측정 체계는 그대로 재사용한다.

## 7. 권장 실행 순서와 완료 기준

| 순서 | 작업 | 완료를 판단할 증거 |
|---|---|---|
| 1 | 현장 검증 세트와 지표 화면 | 촬영 세션별 결과를 다시 재현 가능 |
| 2 | 1인 검출, 품질 필터, 보정, 자동 트리밍 | 기존 검증 세트의 스켈레톤 누락·떨림 감소 |
| 3 | 미등록 행동 거부와 클래스별 임계값 | false accept 감소, macro-F1 향상 |
| 4 | 2D + world 특징, 속도·관절각 추가 | 정면/후면/사선 혼동 감소 |
| 5 | 필요할 때만 ST-GCN/TCN | 같은 고정 검증 세트에서 단순 분류기를 유의미하게 상회 |
| 6 | 다중 카메라 기하 보정 | 카메라 인계 전후 동일 동작의 라벨·좌표 연속성 유지 |

초기 목표치는 제품 요구에 따라 확정해야 하지만, 실험용 통과선으로는 `유효 상반신 프레임 ≥95%`, `연속 누락 p95 <0.5초`, `동작 macro-F1 ≥0.90`, `미등록 행동 false accept ≤5%`를 제안한다. 이 값은 현재 측정 결과가 아니라 앞으로 검증할 **제안 기준**이다.

## 8. 최종 판단

- 현재 합성 데이터 성능은 좋고 자동 테스트도 모두 통과한다.
- 실제 사람 대상 성능은 아직 수치화되지 않았으므로 “정확도가 충분하다”고 결론 낼 수 없다.
- 최대 개선의 첫 단계는 모델 교체가 아니라 실제 검증 데이터, 품질 지표, 미등록 행동 평가다.
- 현재의 한 사람 환경에서는 1인 검출, world 좌표 병행, 품질 기반 필터링, 자동 구간 자르기, 클래스별 거부 임계값이 가장 높은 투자 대비 효과를 낼 가능성이 크다.
- 그 후에도 유사 동작 혼동이 남을 때만 ST-GCN/TCN과 RGB 물체 정보를 도입하는 것이 안전하다.

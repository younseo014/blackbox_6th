## Design Specificity Verdict

**LLM assessment**: Mixed, leaning generic-with-specific-copy. The composition — sidebar nav + topbar + card-grid dashboard — is a completely generic SaaS-admin shell that a project-management tool or POS system could reuse unchanged. ## Overall Impression

The copy and privacy/consent design show real care for a sensitive product — a self-monitoring tool where a 40-60yo shop owner watches their own motion for early signs of cognitive change while running their business solo. But the interface built around that copy is a generic two-mode SaaS dashboard, and the mode split has a structural bug that undermines the whole product: **the target user's own mode has no way to start the camera session that is the entire point of the app.** The biggest opportunity is closing that gap and pulling the mode-switch escape hatch behind a deliberate, confirmed action rather than a one-click topbar toggle.

## What's Working

1. **Consent and privacy copy is product-specific and trustworthy** — explicitly separates "기억 복원" (memory-recall) vs "장기 인지 건강 관찰" (long-term cognitive observation) purposes, states no face/video/audio storage, and is revocable per-purpose.
2. **The "notice" language deliberately avoids diagnostic framing** throughout ("진단이 아닌... 참고 정보", "평소와 다른 흐름" instead of "abnormal") — a self-monitoring cognitive-health tool that resists alarmism is a hard-won, deliberate choice.
3. **Graceful degradation copy** for camera/storage failures reassures rather than just reporting a technical failure (e.g. "영상은 외부로 전송되지 않아요" appears even inside error states).

## Priority Issues

**[P0] The core feature (camera-based observation) is unreachable from user mode**
- **Why it matters**: `userNavItems` contains only `home`, `care`, `settings` — no camera/"today" view. The only places that call `setView("today")` are developer-mode entry points. `completeFirstUserSetup` only flips a mode flag; it never opens the camera. The target persona (the shop owner) has no button anywhere in their own interface that starts the product's entire reason for existing.
- **Fix**: Add a camera/session entry point to user-mode nav, or fold camera-start into the home view's primary CTA.
- **Suggested command**: `/impeccable shape` (this is a missing flow, not a polish pass)

**[P0/P1] Mode-switch escape hatch is a trust/safety hazard, not just clutter**
- **Why it matters**: The mode-switch button sits in the topbar of every view in both modes, one click away, no confirmation, same visual weight as real content. For the target 40-60yo non-technical owner, an accidental click drops them into z-scores, "일치 신뢰도", and fabricated demo personas about themselves — for a product surfacing possible cognitive-decline signals, a confused user landing in a screen of fake results about "someone like them" is a real harm vector, not just UX friction.
- **Fix**: Gate mode switching behind a settings-page action with confirmation, not a persistent topbar toggle.
- **Suggested command**: `/impeccable harden`

**[P1] Observation/"today" screens critically overload working memory**
- **Why it matters**: Occupation select, mode toggle, confidence bar, a 4-stat row, two action-button rows, an active-test panel, a latest-result panel, and full AI classification internals (candidates, z-scores, evidence) all render unconditionally and simultaneously. 5 of 8 cognitive-load checklist items fail here — this is a debug console, not an Operate surface.
- **Fix**: Default to a collapsed/summary state (the app already uses `<details>`/`<summary>` elsewhere) and require explicit expansion for classification internals.
- **Suggested command**: `/impeccable distill`

**[P2] Typography scales too small for the stated 40-60 demographic**
- **Why it matters**: `globals.css` never raises the root font-size, and roughly a third of sized rules sit at 9-13px, used for decision-relevant copy (confidence %, z-score labels, consent fine print). For a product explicitly targeting presbyopia-age users, sub-12px body/support text is a real accessibility miss.
- **Fix**: Raise the floor to ~14px for anything carrying decision-relevant information; reserve sub-12px text for pure decoration.
- **Suggested command**: `/impeccable typeset`

**[P2] Nav icons are unlabeled abstract glyphs**
- **Why it matters**: ⌁, ♡, ⚙ have no `title`/tooltip, forcing recall over recognition; one glyph (⌁) is reused for two different meanings across the two modes.
- **Fix**: Add `title` attributes, or show icon+label at rest even in a collapsed rail.
- **Suggested command**: `/impeccable clarify`

## Persona Red Flags

**Jordan (First-Timer, the actual target shop owner)**: Completes the 3-step first-user setup and lands back on home — but at no point is Jordan shown how to start a camera session, because that entry point doesn't exist in their mode (see P0). Onboarding literally cannot reach the product's core function. The welcome card's small print ("개발자 모드에서 만든 가상 데이터...") also presupposes Jordan already knows there's a developer mode, which a first-timer won't.

**Sam (Accessibility-Dependent)**: Icon-only nav glyphs with no visible label at rest, paired with 9-13px supporting text throughout observation screens, compound into a real barrier for low-vision users — specifically within the 40-60 demographic this product targets. Event nodes also differentiate `payment`/`door`/`booking` types by color alone with no text/icon fallback.

**Alex (Power User, fits developer mode)**: Persona switcher, synthetic datasets, zone setup, and classification evidence work well for Alex once learned. Red flag even here: the classification/performance-test block has no way to collapse when scanning multiple test runs — no summary-first view.

## Minor Observations

- The mode badge in the topbar is the only durable "which mode am I in" signal outside the switch button itself — worth strengthening into a persistent color-coded banner given the P0/P1 issues above.
- The "이어서 하기" (resume booking) savepoint pattern is a nice touch for interrupted tasks and is underused elsewhere.
- The factory-reset button (full data wipe, health-adjacent data) has no type-to-confirm or double confirmation for an irreversible action.

## Questions to Consider

- If the shop owner literally cannot start a camera session from their own mode, was "user mode" ever tested end-to-end by someone who wasn't also a developer?
- Given this product is self-surveillance for possible cognitive decline, is a one-click, unconfirmed toggle into a full "debug persona" UI with fabricated data about people who look like the user actually safe, or could a confused/anxious user misread it as their own real results?
- The design system (cards, kickers, sidebar) is interchangeable with any SaaS dashboard — if you stripped the Korean copy, would anything on screen tell you this app watches an aging person's own body for signs their mind is changing?
